# Farm Data Processor

![GitHub release (latest by date)](https://img.shields.io/github/v/release/CIAT-DAPA/ganabosques_farm_data_processor) ![](https://img.shields.io/github/v/tag/CIAT-DAPA/ganabosques_farm_data_processor)

The Farm Data Processor container operates as an ETL (Extract, Transform, and Load) process focused on querying and processing information on livestock farms and conservation areas. It operates in three phases: the first involves constructing polygons using buffers, based on information from SAGARI; the second focuses on quality control of the polygons generated by GeoFarmer; and the third is responsible for delimiting polygons corresponding to conservation areas, considering official sources such as National Natural Parks, Regional Natural Parks, Páramo Zones, and Agricultural Frontiers.


## 🚀 Installation

1. Clone the repository:
```bash
git clone https://github.com/CIAT-DAPA/ganabosques_farm_data_processor.git
```

2. Create a virtual environment:
```bash
python -m venv env
```

3. Activate the virtual environment:
```bash
env\Scripts\activate  # Windows
source env/bin/activate  # Linux/Mac
```

4. Install dependencies:
```bash
pip install -r requirements.txt
```


## 🧱 Project Structure

The project follows a modular structure where each folder represents a specific step of the ETL pipeline for processing livestock farm data:

```bash
├── src/
│   ├── get_data_sagari/               # Step 1: Read and parse raw SAGARI data
│   ├── quality_control_coordinates/   # Step 2: Perform quality control on coordinates
│   ├── polygons_buffers/              # Step 3: Generate polygons with buffers
│   ├── save_farm/                     # Step 4: Save farms and polygons to MongoDB
│   ├── tools/                         # Common utilities (logging)
│   ├── main.py                        # Main pipeline entry point
│   ├── .env                           # Environment config (MongoDB, Geoserver)
│   └── config.py                      # Loads environment variables and constants (DB credentials, UGG mappings) 
├── tests/                             # Unit tests for each processing step
├── pytest.ini                         # Pytest config
├── requirements.txt                   # Python dependencies
└── README.md
```

## 🚀 How to Run the Pipeline

You can execute the full pipeline or selected steps via the command line:

### 🧭 Available Steps

| Step | Description                              |
|------|------------------------------------------|
| 1    | Get data from source (SAGARI/GeoFarmer)  |
| 2    | Validation of coordinate quality         |
| 3    | Calculation of geospatial buffers        |
| 4    | Save property information in MongoDB     |

### 🧾 Arguments

--source (-s)         Required. Options: SAGARI, GEOFARMER  
--process (-p)        Optional. List of step numbers to execute (e.g., 1 2 4)  
--from_step (-f)      Optional. Execute from a step number onwards (e.g., 2)

You cannot use `--process` and `--from_step` simultaneously.

### 📌 Run all steps:

```bash
python main.py -s SAGARI
```

### 🛠 Run selected steps:

```bash
python main.py -s SAGARI -p 1 3
```

### 🔁 Run from a specific step:

```bash
python main.py -s SAGARI -f 2
```

---

### 📖 Help

```bash
python main.py -h
```

## 🛠️ Environment Variables

Set these values in your `.env` file or system environment:

```bash
# URL of the GeoServer instance
URL_GEO=http://localhost:8080/geoserver

# Local path where the results are to be temporarily stored
WORKSPACE=D:/ganabosques/data/

# Replace GEO_USER with your actual GeoServer username
GEO_USER=admin

# Replace GEO_PWD with your actual GeoServer password
GEO_PWD=admin

# Name of the GeoServer workspace, which must be created before running the code
GEO_WORKSPACE_ADMIN=administrative

# MongoDB URL enabled 
MONGO_URI=mongodb://usuario:contraseña@localhost:27017

# Name of the MongoDB database where the information is stored
MONGO_DB_NAME=midatabase

# Local path where the raw input data is stored.
DATA=D:/data/sagari

# URL of the Geofarmer API
GEOFARMER_BASE_URL=https://api-v3.geocitizen.org

# Geofarmer API credentials for each entreprise. These credentials are obtained from the Geofarmer platform and must be set for each enterprise you want to process.
COLACTEOS_CLIENT_ID=

COLACTEOS_CLIENT_SECRET=

...

NEGOCIOS_VERDES_CLIENT_ID=

NEGOCIOS_VERDES_CLIENT_SECRET=
```

## 📂 Outputs

The results are stored in the folder configured in the `WORKSPACE` variable, in subdirectories organized by steps:

1. `01_tmp_get_data_sagari`
2. `02_tmp_quality_control_coordinates`
3. `03_tmp_polygons_buffers_data_frame`
4. `04_tmp_save_movement`

### 📃 Logging

A `main_pipeline.log` file is generated inside the `outputs` directory containing the execution log.
